## Part I: 技術的公正性の監査結果

### 1. シミュレーション・ループ（不正なし）

**検証ファイル**: `autotrader/backtest/year_runner.py`, `autotrader/backtest/simulator.py`

- ローソク足はインデックス順に1本ずつ処理される（`CandleArrays.get_candle(idx)`）
- 将来のローソク足にアクセスする機構は存在しない
- シグナルは現在の足で生成され、**次の足のOpen価格**で約定する（Pending Signal方式）

```
[Bar N] シグナル生成 → _pending_signal に保存
[Bar N+1] _execute_pending_entry(candle) → candle.open + spread + slippage で約定
```

**結論: 先読みなし。次足Open約定は業界標準の保守的手法。**

### 2. データアクセス制御（不正なし）

**検証ファイル**: `autotrader/decision/unified/trade_bot.py` (lines 2755-2801)

`_get_current_row()` メソッドが全データアクセスのゲートキーパーとして機能:

```python
while last_idx + 1 < n and time_arr[last_idx + 1] <= ct:
    last_idx += 1
if time_arr[last_idx] > ct:
    return None  # 未来データへのアクセスを遮断
```

- 全タイムフレーム（M1〜D1）で同一メカニズムが適用
- HTFデータも `np.searchsorted(time_arr, ct, side="right") - 1` で正しくアライメント
- `set_market_data()` でDataFrame全体が渡されるが、アクセスは上記メソッドで時間制限

**結論: 将来データへのアクセスはコード上不可能。**

### 3. テクニカル指標の事前計算（不正なし）

**検証ファイル**: `autotrader/backtest/runner.py` (lines 445-549), `autotrader/calculator/precompute.py`

全指標が年間データ全体に対して事前計算される。使用される指標:

| 指標 | 計算方式 | 先読み有無 |
|------|---------|-----------|
| SMA/EMA | `pandas_ta` rolling | なし（後方参照のみ） |
| RSI | 過去N期間の変化率 | なし |
| MACD | EMA差分 | なし |
| ATR | True Range の平滑化 | なし |
| ADX | DI+/DI- の平滑化 | なし |
| Bollinger Bands | SMA ± σ | なし |
| Stochastic | 期間内の高安比率 | なし |
| Volume Ratio | `rolling(20).mean()` | なし（`center=False`） |

**SwingAnalyzer（SMC指標）**: `lookforward=2` で先読みあり。ただし `shift(lookforward)` で遅延補正済み。さらに、**このコードパスは主要バックテストパイプラインでは使用されていない**（未使用コード）。

**PivotHigh/Low**: `pivot_right=5` で先読みあり。ただし、こちらも **主要パイプラインでは未使用**。

**結論: 使用中の全指標は後方参照のみ。先読みがある指標は未使用コードパスに存在するのみ。**

### 4. SL/TP評価（不正なし）

**検証ファイル**: `autotrader/backtest/simulator.py` (lines 551-700)

- SL/TP は現在足の `high`/`low` で評価（将来足は参照しない）
- ギャップ時（始値がSL/TPを超えて始まった場合）は `candle.open` で約定（より不利な価格）
- SLとTPが同一足内で両方触れる場合、**SLが優先**（保守的）

```python
# BUY のSL判定
if candle.low <= sl:
    if candle.open < sl:  # ギャップダウン
        return (candle.open - slip - spread, ExitReason.STOP_LOSS, sl)
    return (sl - slip - spread, ExitReason.STOP_LOSS, sl)
```

**結論: SL/TP処理は保守的に実装。ギャップ処理も適切。**

### 5. スプレッド・スリッページモデル（概ね適切）

**検証ファイル**: `config/symbol_presets.yaml`, `autotrader/backtest/simulator.py`

| ペア | 設定スプレッド(pips) | スリッページ(pips) | 実勢（小売FX） | 評価 |
|------|---:|---:|---:|------|
| EURUSD | 1.0 | 0.3 | 0.8-1.5 | 妥当 |
| GBPUSD | 1.5 | 0.3 | 1.0-2.0 | 妥当 |
| USDJPY | 1.5 | 0.5 | 1.0-2.0 | 妥当 |
| EURJPY | 2.0 | 0.7 | 1.5-3.0 | 妥当 |
| GBPJPY | 3.0 | 1.0 | 2.0-4.0 | 妥当 |
| AUDJPY | 2.0 | 0.7 | 1.5-3.0 | 妥当 |
| CADJPY | 2.5 | 0.7 | 2.0-4.0 | 妥当 |
| CHFJPY | 2.5 | 0.7 | 2.0-4.0 | 妥当 |

- エントリー: `open + half_spread + slippage`（不利側に適用）
- SL決済: `sl - slippage - spread_factor`（不利側に適用）
- TP決済: `tp - slippage`（不利側に適用）
- 手数料: 0.0円/lot（日本のFXブローカーの一般的な設定）

**懸念点**: ヘッドラインの結果は**固定スプレッド**モードで計算されている。ニュース時や早朝のスプレッド拡大は反映されていない。ただし、スプレッドストレステスト（x3.0でPF 1.54維持）は別途実施されており、スプレッド変動への耐性は確認済み。

**結論: スプレッド設定値は小売FXの実勢と整合。スリッページも全方向で不利側に適用。**

### 6. 制約・フィルタシステム（不正なし）

**検証ファイル**: `autotrader/constraint/` 配下全ファイル

| フィルタ | アクセスデータ | リアルタイム利用可能性 | 先読み |
|---------|-------------|-------------------|--------|
| HardGuard（マージン/日次損失/時間制限） | 現在時刻, 口座状態 | ○ | なし |
| SoftGuard（スプレッド/ボラ/連敗） | 現在足の指標値 | ○ | なし |
| EdgeValidator（回路遮断器） | 過去の確定トレード | ○ | なし |
| SessionFilter（キルゾーン） | 現在時刻 | ○ | なし |
| EventFilter（経済指標） | 現在時刻 ± 30分 | ○（公開カレンダー） | なし* |
| VolatilityFilter（ATRパーセンタイル） | 過去200本のATR | ○ | なし |
| MicroReversalFilter | 現在M1足データ | ○ | なし（無効） |
| M1ExecutionGate | 現在M1足データ | ○ | なし（無効） |

*EventFilterの+30分ウィンドウは、経済指標カレンダーが事前公開されるため、リアルタイムでも利用可能な情報。

**結論: 全フィルタは現在時刻以前のデータのみを使用。将来情報による選択的損失回避は行われていない。**

### 7. ポジションマネージャ（不正なし）

**検証ファイル**: `autotrader/decision/unified/risk/position_manager.py`

| 機能 | 使用データ | 先読み |
|------|-----------|--------|
| トレーリングストップ | `candle.close`（足確定値） | なし |
| 部分利確（1R/2R） | `current_r`（close基準） | なし |
| ブレイクイーブン移動 | `current_r >= 1.0` | なし |
| 停滞決済 | 経過時間 + 最高到達R | なし |
| コンセンサス反転決済 | 現在足のスコア | なし |
| 時間制限決済 | 経過時間 | なし |

**BREAKEVEN PnL処理**: コード上 `ExitReason.BREAKEVEN` の場合にPnLを0に強制する処理が存在する（simulator.py:1167-1170）。しかし、**実際のバックテスト結果では BREAKEVEN 決済のトレードは0件**。このコードパスは実質的にデッドコードであり、パフォーマンスに影響していない。

**結論: 決済ロジックに先読みなし。全決済判断は `candle.close` または `high/low`（SL/TP）に基づく。**

## Part I 総合判定

> **バックテストのコード実装において、先読みバイアス（Look-Ahead Bias）、データリーク、または意図的な不正行為は検出されなかった。**

シミュレータは以下の業界標準手法を正しく実装している:
- 次足Open約定（Pending Signal方式）
- SL/TPのインラバー評価（high/low使用、ギャップ処理あり）
- SL優先評価（SL/TP同時到達時）
- 全方向への不利スリッページ適用
- 時間ゲートによるデータアクセス制御

## Part II: パフォーマンスが異常に高い理由の分析

技術的不正が見つからなかったため、次に「なぜこれほど性能が良いのか」を分析する。
結論として、**正当な理由**と**注意すべきリスク**の両方が存在する。

### A. 正当にパフォーマンスを押し上げている要因

#### A-1. 極端なトレード選別（最大の要因）

本システムは**13層以上のフィルタ**を通過したシグナルのみを執行する:

```
1. 8タイムフレーム各TFの最低スコア要件
2. 50% TFアライメント要件
3. 60% コンフリクト比率上限
4. スコア均一性チェック（CV < 1.0）
5. エントリーTF方向一致要件
6. コンセンサス閾値 18.0〜22.0（レジーム依存）
7. BCA方向性エッジゲート（min_edge 0.60〜0.70）
8. HardGuard（8項目以上の即時拒否条件）
9. SoftGuardペナルティ（スプレッド/時間/ボラ/連敗/MTF矛盾/トレンド/ボリューム）
10. ペナルティ上限チェック（0.3〜0.5ペア別）
11. トレンド強度最大フィルタ（0.7〜0.85）
12. MACDスロープデッドゾーンフィルタ
13. レジーム別追加閾値（CHOPPY時 +3.0）
```

**結果**: 8ペア×3年間で3,022トレード = **1ペアあたり1日約0.5回**のトレード頻度。
機会の大部分を見送り、最も条件の良いエントリーのみを選択する構造。

**勝率86%の数学的妥当性**: 13層のフィルタがそれぞれ独立に約90%の精度で「悪いトレード」を排除すると仮定すると、通過するトレードの質は非常に高くなる。これは高勝率型スキャルピング戦略の一般的な特性と整合する。

#### A-2. 攻撃的なリスク管理

- **base_risk_pct = 0.005**（0.5%リスク/トレード）: 一般的な推奨値（1〜2%）の1/2〜1/4
- **max_positions = 4**: 最大4ポジション同時保有
- **max_same_direction_jpy = 3**: JPY同方向は最大3ペア
- **global_max_exposure_lot = 5.0**: 全体のロット上限
- **DDに応じた動的ロット縮小**: DD > 0.8% で早期にロット縮小開始

この「超保守的」なリスク管理により、1トレードの損失がエクイティに与える影響は極めて小さく、DD < 2% が構造的に維持される。

#### A-3. 短い保有時間

- 平均保有時間: 68分（約1時間）
- 中央値: 43分
- 市場滞在率: 8〜13%

短い保有時間は夜間やニュース時のギャップリスクを大幅に低減し、DD抑制に寄与する。

#### A-4. 多層ポジション管理

- 1Rで5%部分利確 → SLをBEに移動 → TPを無効化し残りはトレーリング
- 2Rで追加5%部分利確
- 停滞検知による早期撤退（30〜120分）
- 利益反転ガード

この構造により、**多くの潜在的損失トレードが小利益または±0で終了**する。勝率が高い根本的な理由は、システムが「負けにくい」構造になっていること。

#### A-5. 16年間の一貫性

| 期間 | PF | 勝率 | 年間トレード数 |
|------|-----|------|-------------|
| IS 2023-2025 | 3.52 | 86.0% | 1,007 |
| OOS 2020-2022 | 3.34 | 84.9% | 768 |
| DeepOOS 2010-2019 | 3.13 | 84.6% | 685 |

**OOS (2020-2022) のPF 3.34 は IS (2023-2025) のPF 3.52 と遜色ない。**
**DeepOOS (2010-2019) の10年間でもPF 3.13、勝率84.6%を維持。**

これは純粋なカーブフィッティングでは達成困難。16年間（2010-2025）にわたって安定したパフォーマンスは、何らかの構造的エッジの存在を示唆する。

### B. 注意すべきリスク要因（パフォーマンスを過大評価する可能性）

#### B-1. 過剰最適化リスク（重大）

**パラメータ数 vs トレード数**:
- チューナブルパラメータ: 約150〜200個（UnifiedBotConfig約120 + PositionManagerConfig約55 + ペア別オーバーライド40〜80）
- ISトレード数: 3,022
- **パラメータあたりのトレード数: 約15〜20**
- 学術的推奨: パラメータあたり50〜100トレード以上

パラメータ数に対してトレード数が不足しており、過剰適合のリスクが存在する。

**ただし反論**: DeepOOS（2010-2019）の10年間で6,852トレード、PF 3.13はパラメータチューニング期間外のデータであり、単純なカーブフィッティングではこの一貫性は出ない。

#### B-2. OOS汚染の可能性（中程度）

Gitコミット履歴には28件以上の最適化関連コミットがあり、パラメータチューニングが反復的に行われた痕跡がある。「OOS」と定義された2020-2022年のデータが、チューニング時に結果確認用として参照された可能性がある。

**ウォークフォワード検証の未実施**: `walk_forward.py` に検証インフラが実装されているが、**本番パラメータに対して実行された形跡がない**（Git履歴に該当コミットゼロ件）。

**ただし反論**: DeepOOS（2010-2019）は明確にチューニング範囲外であり、ここでのPF 3.13は汚染の影響を受けていない。

#### B-3. 通貨ペア生存者バイアス（中程度）

- テスト対象: 12ペア
- 採用: 8ペア（6JPY + EURUSD + GBPUSD）
- **除外: 4ペア**（AUDUSD WR72.8%/DD7.98%, NZDUSD WR70.3%/DD7.29%, USDCHF, USDCAD）

パフォーマンスが低い4ペアを除外してポートフォリオを構成しているため、報告される集約指標は上方バイアスを持つ。

**ただし反論**: ペア選択は実運用でも当然行われる判断であり、全ペアを無差別に運用する義務はない。除外ペアのデータが透明に開示されている点は評価できる。

#### B-4. JPY相関リスク（中程度）

8ペア中6ペアがJPY建て。JPY急変時（日銀介入等）に同方向ポジションが同時に損失を出すリスクがある。`max_same_direction_jpy = 3` の制限はあるが、相関リスクを完全には排除しない。

Sharpe比 7.34 は、相関の高い6ペアを「独立した分散投資」として計算している可能性があり、**相関調整後のSharpe比はこれより低い**と推定される。

#### B-5. 固定スプレッドモデルの限界（軽微）

ヘッドラインの結果は固定スプレッドで計算されており、以下を反映していない:
- ニュース時のスプレッド拡大
- 早朝/深夜のスプレッド拡大
- 週明けのスプレッドジャンプ

**ただし反論**: スプレッドx2.0でもPF 2.19、x3.0でもPF 1.54を維持。スプレッド変動に対する十分なバッファがある。

#### B-6. DD抑制によるSharpe比の人為的膨張（中程度）

DD > 0.8% でポジションサイズを積極的に縮小する機構により、エクイティカーブが人為的に平滑化される。これによりSharpe比が実態以上に高く計算される。

**Sharpe比 7.34 は通常のFXトレーディングでは非現実的に高い数値**。ヘッジファンドの上位1%でも2.0〜3.0が限界。ただし、この高Sharpe比はDD抑制メカニズムとnon-compoundモード（毎月初期資金にリセット）の組み合わせで数学的に説明可能。

#### B-7. ペア別パラメータの微調整（中程度）

`symbol_presets.yaml` には各ペア固有のオーバーライドが5〜10個あり、バックテスト結果のコメント付きで最適値が選択されている:

```yaml
# DZ-T2検証: PF 4.22→4.86, DD 2.48→2.06%
# P2結果: 0.70が最良 (DD -1.4pp vs 0.65)
# RL-T20: +450K, WR +0.36pp, DD -0.30pp
```

これは典型的なデータスヌーピングのパターン。各パラメータを複数候補から選択した場合、パラメータ空間の探索により偶然良い結果を見つけるリスクがある。

## Part III: 監査結論

### 結論1: 技術的不正は検出されなかった

バックテストコードに以下の不正は**存在しない**:
- 先読みバイアス（Look-Ahead Bias）
- 将来データの参照
- 非現実的な約定価格
- スプレッド/スリッページの過小評価
- フィルタによる将来損失の選択的回避

シミュレータは業界標準の手法（次足Open約定、SL/TPインラバー評価、全方向スリッページ）を正しく実装している。

### 結論2: パフォーマンスが高い主要因は「極端な選別」

13層以上のフィルタと高いコンセンサス閾値（18.0〜22.0）により、全機会の大部分を見送り、最も条件の良いエントリーのみを選択する構造になっている。これは「勝てる時だけ勝負する」戦略であり、高勝率・低DDは構造的に説明可能。

### 結論3: 過剰最適化リスクは存在する

150以上のパラメータが3,022トレードに対してチューニングされており、過剰適合の可能性は否定できない。ウォークフォワード検証が未実施であり、OOS期間の独立性にも疑問がある。

**ただし、DeepOOS（2010-2019、10年間）でPF 3.13・勝率84.6%を維持している事実は、純粋なカーブフィッティングでは説明困難であり、何らかの構造的エッジの存在を強く示唆する。**

### 結論4: ライブ実績での検証が不可欠

以下の要因はバックテストでは完全に再現できない:
- リアルタイムのスプレッド変動（特にニュース時）
- 約定遅延・スリッページの変動
- 流動性枯渇時の約定拒否
- ブローカーによる約定品質の差異
- 心理的要因（システム停止判断等）

**ライブトレーディングでのパフォーマンスはバックテストより劣化する可能性が高い。**
ただし、スプレッドx3.0でもPF 1.54を維持するバッファがあり、相当の劣化に耐えうる構造。

## Part IV: リスク評価サマリ

| リスク要因 | 深刻度 | パフォーマンスへの影響 |
|-----------|--------|-------------------|
| 先読みバイアス | **なし** | 該当なし |
| データリーク | **なし** | 該当なし |
| スプレッド設定の非現実性 | **なし** | 該当なし |
