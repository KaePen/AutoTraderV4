## 発見1: SL_HIT 3件はいずれも20〜26分以内の短時間被弾

```
08:06 BUY 212.738  →  08:27 SL_HIT 212.538（-20.0pips、20分）
08:27 BUY 212.585  →  08:50 SL_HIT 212.385（-20.0pips、23分）
12:42 BUY 212.767  →  13:08 SL_HIT 212.557（-21.0pips、26分）
```

- SL幅は一貫して **20〜21pips**（設定通り正確に損切り）
- 欧州オープン直後（08:00〜09:00 GMT）の荒い動きが連続被弾の原因と推定
- 08:06と08:27のエントリーは**21分間隔の連続エントリー**（SL被弾直後に再エントリー）

### 連続エントリーについて

SL被弾後すぐに再エントリーしているのは、コンセンサスがBUYを継続的に出し続けているため。
ただし、3回連続での同方向SL被弾（累計-8,024円）はEdgeValidatorのクールダウンで抑制される想定。
→ **クールダウンが機能したかどうかを確認が必要**

## 発見2: BE移動後のEXTERNAL_CLOSE は実質1Rでの手動決済

```
#3: entry=212.508  SL=212.558（+5pips, BE移動済）  exit=212.708（+20.3pips）
    → 初期SL幅20pips基準の達成R = 1.02R → +203円で手動決済

#5: entry=212.579  SL=212.629（+5pips, BE移動済）  exit=212.798（+21.9pips）
    → 初期SL幅20pips基準の達成R = 1.09R → +219円で手動決済
```

**「2000円→200円」のパターンとは異なる**: TP（30pips）まであと10pipsの段階で手動決済。
元々1R≒200円のポジションサイズであり、+200円は適正な利益。

ただし、TPまで到達していれば：
- #3: 29.8pips → +305円
- #5: 30.6pips → +333円

## 発見3: OPEN中のポジション（3/25）でhighest_r=1.37

`local_state.db` より：
- `highest_r = 1.37`（最大1.37R到達済み）
- `trailing_activated = 1`（トレーリング動作中）
- `partial_closed_1r = 1` / `tp_disabled = 1`（1R部分利確・TP無効化済み）
- `early_be_applied = 1`（BE移動済み、SL幅5pips上に設定）

このポジションは `profit_reversal_enabled = False`（デフォルト）のため、
含み益が大幅に削られても自動決済されない状態。
→ **これが「2000円→200円」リスクにさらされているポジション**

## 問題整理と対応方針

### 問題1: SL被弾の連続（最大損失源）

| 項目 | 状況 |
|------|------|
| 被弾回数 | 3回（同日、同ペア） |
| SL幅 | 20pips（一定） |
| 被弾時間 | 全て20〜26分以内 |
| 時間帯 | 欧州オープン直後（08時台） + 13時台 |
| 損失 | 合計-8,024円 |

**仮説**: 欧州オープン時の高ボラティリティで20pipsのSLが狭すぎる。
または、コンセンサスBUYが出ていても実際の価格動向がBUYではない（シグナル品質の問題）。

### 問題2: OPEN中ポジションの含み益保護不足

- `profit_reversal_enabled = False` → 1.37Rの含み益に対してガード機能なし
- Stage2トレーリング（1.5R以上で ATR×1.2）はまだ未発動
- このポジションが逆行した場合、全含み益を吐き出す可能性あり

### 問題3: 手動決済（EXTERNAL_CLOSE）が多い

- システムの自動エグジットが機能せず、ユーザーが手動決済している
- `consensus_exit_threshold=6.0` は閾値が高く、中程度の反転では不発

## BTキュー投入済みの検証案との対応

| 案 | 内容 | 対応する問題 |
|----|------|------------|
| case-A | profit_reversal有効化 | OPEN中ポジションの含み益蒸発 ← **最優先** |
| case-B | early_profit_guard上限拡大 | 1R以上の利益域での保護 |
| case-C | consensus_exit閾値緩和 | 手動決済が必要な状況を減らす |
| case-D | Stage2トレーリング早期化 | 1.5R前の大利益を保護 |
| case-E | 組み合わせ | 複合効果 |

SL被弾問題（問題1）はBTキューでは直接対処していないため、
BTの結果を見てから追加で `initial_sl_pips` 調整を検討する。
