# スコアリング重み構造改善計画

## Context

consensus_scoreの予測力ゼロ（r=-0.001）問題の根本原因を、ScoreBreakdown相関分析により特定した。
問題は「データにフィットしていない」のではなく「スコアリングの構造的矛盾」に起因する。

---

## 発見1: ストキャスティクス・ボーナスが逆効果

### データ
| stoch値 | 件数 | WR% | 意味 |
|---------|------|-----|------|
| -1.5（過買/過売ペナルティ） | 509 | **85.5%** | モメンタムが強い |
| 0.0（範囲外） | 292 | 75.7% | 中立 |
| +0.5（順方向ボーナス） | 35 | **71.4%** | モメンタムが弱い |

全レジームで一貫（RANGE: 82.6→76.3→74.1%, BREAKOUT: 91.2→89.1%, CHOPPY: 85.0→56.7%）

### 構造的根拠（過剰フィッティングではない理由）

**このシステムはモメンタム追従型**（トレンド+MACD確認でエントリー）。
ストキャスティクスは本来**平均回帰型**のオシレーターであり、「買われすぎ=売りシグナル」と解釈する。

しかしモメンタム追従では**逆の意味**を持つ:
- BUYでstoch>80（「過買」）= **上昇モメンタムが強い** = エントリー品質が高い
- BUYでstoch 20-50（「順方向ボーナス」）= **まだ動いていない** = モメンタム未確認

これは定量金融で広く知られた原則: **トレンド環境ではオシレーターの過買/過売は継続シグナル**。
2024年固有のパターンではなく、モメンタム追従システムの構造的特性。

### 修正案
```
stoch_zone_bonus: 0.5 → 0.0       # 順方向ボーナスを無効化
stoch_extreme_penalty: 1.5 → 0.0  # 過買/過売ペナルティも無効化
```

**理由**: ストキャスティクスの判断をスコアに加算しない。ペナルティもボーナスも
モメンタム追従の文脈では逆効果。指標自体は`StrengthConfig`でRSIと合わせて参照するため
完全に削除するわけではない。スコアリングへの寄与のみゼロにする。

## 発見2: trend=2.5（MACD未確認エントリー）の低品質

### データ
| trend値 | 意味 | 件数 | WR% | MFE/MAE |
|---------|------|------|-----|---------|
| 5.0 | 完全トレンド+MACD一致 | 519 | 82.9% | 2.09 |
| 4.0 | トレンド+MACD一致 | 230 | 83.9% | 2.25 |
| **2.5** | **トレンドのみ（MACD不一致）** | **87** | **66.7%** | **1.16** |

### 構造的根拠

このシステムのエッジは「MTFコンセンサス × MACDモメンタム確認」にある。
trend=2.5はMACDが方向を確認していない = **システムのコアエッジが欠如**した状態。

これらのエントリーがconsensus閾値を通過できるのは、他指標（HTF +4.0, EMA +0.5等）の
加算で閾値を超えるため。しかし**根幹のモメンタム確認なしにエントリーする**ことは
システム設計の意図に反する。

### 修正案
```
trend_only_score: 2.5 → 1.5  # MACD未確認時のスコアを引き下げ
```

**理由**: 完全にゼロにすると過剰に制限的。1.5に下げることで、他指標が十分に強い場合
（HTF完全一致等）のみ通過可能になる。MFE/MAE 1.16（逆行が順行とほぼ同等）は
エントリー品質として不十分であり、閾値を上げて「確信度の高いMACD未確認」のみ残す。

## 変更しないもの: EMAクロスペナルティ

### データ
| EMA | 件数 | WR% | AvgPips | consensus平均 |
|-----|------|-----|---------|-------------|
| -2.5（逆行ペナルティ） | 53 | 83.0% | +11.1 | 18.8 |
| +0.5（順行ボーナス） | 782 | 81.3% | +7.2 | 19.2 |

### 変更しない理由: 生存者バイアス

EMAペナルティ群のconsensus最低値は18.1（ボーナス群と同等）。
-2.5のペナルティを受けてなお閾値18.0を超えたということは、
**他の全指標が極めて強い**トレードだけが選抜されている。

これはEMA逆行が良いシグナルなのではなく、**閾値フィルタリングの選抜効果**。
EMAペナルティを外すと、低品質エントリーが流入して全体の品質が低下する。

→ **現行設定が正しく機能している。変更不要。**

## 実装計画

### 変更ファイル
- `autotrader/decision/unified/config.py`: デフォルト値変更（`EvaluatorConfig`）
- 変更なし: `timeframe_evaluator.py`（M3で設定参照化済みのため、configの値変更のみで反映）

### 変更パラメータ（2つのみ）
```yaml
# EvaluatorConfig デフォルト値
stoch_zone_bonus: 0.5 → 0.0           # ストキャスティクスボーナス無効化
stoch_extreme_penalty: 1.5 → 0.0      # ストキャスティクスペナルティ無効化
trend_only_score: 2.5 → 1.5           # MACD未確認トレンドのスコア引下げ
```

### BT検証方法
1. クイック検証（2024年）: overridesで3パラメータ変更
2. ベースライン比較: PF/WR/DD/Sharpe/Trades
3. 有望ならIS検証（2023-2025）→ OOS検証（2020-2022）の階層検証

### 過剰フィッティング検証
- 2024年で発見 → 2020-2022（OOS）で再現すれば構造的
- 再現しなければデータ固有のパターンとして不採用

### 期待する変化
- **トレード数減少**: trend=2.5の87件の一部が閾値未達でフィルタ、stoch bonus の35件が閾値未達
- **WR向上**: 低品質エントリーの除外
- **PF向上**: WR向上に伴う品質改善
- **DD改善可能性**: 低品質エントリー起因のDDが減少
